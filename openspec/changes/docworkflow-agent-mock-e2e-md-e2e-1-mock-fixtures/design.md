# MD-E2E-1 Mock Fixtures Design

## Scope

This change implements fixture and validator contracts only. It does not implement the local mock session runner, standard gate migration, README closeout sync or live-agent path.

## Fixture Strategy

Two fixture families live under `tests/docworkflow-agent-delivery/mock-data/`: `large-parent` and `small-direct`. Each fixture root contains one source spec, one `manifest.json` and one minimal `mock-target/` root. Runtime outputs are generated by later runner slices and are not committed as positive fixture outputs.

## Validator Strategy

The validators use Node.js to match the existing deterministic Agent Delivery validator style. `mock-manifest-schema.js` validates positive fixture manifests and source/target presence. `forbidden-real-fixture.js` scans passed files or directories for forbidden real fixture paths and compatibility fixture markers.

## Boundaries

`MD-E2E-1` may not edit legacy standard gate scripts or make KI-fuer-KMU a historical compatibility input. If fixture ambiguity requires runner behavior, stop and re-enter hardening instead of widening into `MD-E2E-2`.
