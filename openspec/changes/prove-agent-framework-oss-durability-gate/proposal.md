## Why

The Microsoft Agent Framework pilot must not begin until an executable gate proves that its exact durable-execution dependency tuple has a production-capable, self-hostable open-source backend with no unavoidable framework or managed-workflow-service licence cost. Documentation alone cannot establish runtime compatibility, worker replacement behavior, or isolation from the existing LangGraph pilot.

## What Changes

- Add a reproducible Gate 0 command that validates the pinned source, package lock, runtime, configuration, contract, backend, licence, and cost manifest before any workflow starts.
- Add an isolated two-worker durability probe that either demonstrates continuation of one run after a controlled worker termination without duplicate effects, or emits a documented no-go and stops the Microsoft candidate.
- Capture machine-readable and human-readable evidence correlated to exact revisions and immutable dependency identities.
- Verify before/after fingerprints for the LangGraph pilot, Cloudflare relay, macOS operation, runtime data, worktrees, and ProBara CRM boundaries.
- Exclude Temporal and paid managed workflow services from dependencies and fallback configuration.

## Capabilities

### New Capabilities

- `agent-framework-oss-durability-gate`: Reproducible, fail-closed qualification of the Microsoft Agent Framework durability tuple and its isolated worker-replacement evidence.

### Modified Capabilities

None.

## Impact

- Adds Gate 0 tooling, tests, manifests, and evidence under a dedicated top-level gate workspace without starting the later product pilot.
- Adds an OpenSpec change and updates the first Microsoft pilot issue with its verified outcome.
- Reads but does not modify the existing LangGraph pilot, Cloudflare relay, macOS services, runtime state, worktrees, GitHub configuration, or ProBara CRM.
- May stop with a no-go if the exact supported production OSS backend path cannot be proved; subsequent Microsoft pilot tickets then remain unstarted.
