# Acceptance Criteria Matrix

| Issue-06 criterion | Public observation | Expected result | Direct verification |
|---|---|---|---|
| Active OpenSpec contract before implementation | Strict OpenSpec CLI validation | Proposal, design, capability spec, write-set, tasks, and direct verification plan are valid before production edits | `openspec validate continue-run-after-human-feedback --strict` |
| Human change request resumes the existing run/worktree/PR | Signed feedback POST followed by workflow GET and controlled ownership effects | Run ID and implementation worktree stay unchanged; no second worktree/branch/PR is created | `test_human_feedback_reuses_run_ownership_and_fully_verifies_a_new_head` |
| Only configured-human, explicit, associated feedback is accepted | Signed approval/bot/other-user/empty/unrelated-PR cases and adapter identity contract | No feedback batch or writer effect for non-feedback activity | `test_non_feedback_pr_activity_has_no_continuation_effect`; `test_github_adapter_recognizes_only_the_configured_human_user` |
| Production relay forwards the supported lifecycle events | Cloudflare Worker ingress contract with the configured repository/event allowlists | `pull_request_review:submitted`, `pull_request_review_comment:created`, and `pull_request:closed` are durably queued; repositories and other actions remain unchanged | `allows the configured lifecycle delivery $event:$action`; full relay `npm run check` |
| Every feedback batch has its own three-round counter and only new feedback | Workflow GET batch history and captured public worker assignments | An exhausted initial repair does not consume the new batch; later batches each start at one; a batch has no fourth writer invocation | `test_feedback_gets_round_one_after_the_initial_repair_batch_exhausted_three_rounds`; `test_each_later_human_feedback_batch_starts_with_its_own_counter_and_context`; `test_one_human_feedback_batch_stops_after_exactly_three_attempts` |
| New commit invalidates prior-head qualification | Workflow GET superseded evidence/review history plus controlled label projection | Existing PR receives a distinct head; `agent-running` replaces stale `verified`/`awaiting-review` and stale human-handoff labels | `test_human_feedback_reuses_run_ownership_and_fully_verifies_a_new_head` |
| Evidence, deterministic verification, and three reviews are fully regenerated | Workflow GET attempt evidence, deterministic result, and review history | Every feedback head has current-head evidence and three fresh review results; old verification cannot qualify a failed new head | `test_feedback_head_cannot_reuse_old_verification_and_runs_all_reviews_each_round` |
| Authorized human merge closes the same persistent lifecycle | Signed merge POST after restart followed by workflow GET | Same run and checkpoint become `completed`; feedback/review history is unchanged and terminal merge metadata is durable | `test_authorized_human_merge_completes_the_same_run_and_checkpoint_after_restart` |
| Other close activity cannot complete the run | Signed non-merged, other-user, bot, unrelated-PR, and wrong-head POST cases | Run stays running and has no completion record | `test_pr_close_without_the_correlated_human_merge_does_not_complete_the_run` |
| Workflow never merges, deploys, or releases | Controlled source/writer/reviewer effect counts across merge plus absence of such operations from workflow ports | Merge delivery adds no worktree, writer, source publication, reviewer, merge, deploy, or release effect | `test_authorized_human_merge_completes_the_same_run_and_checkpoint_after_restart` |
