# Acceptance Criteria Matrix

| Issue-08 criterion | Public observation | Expected result | Direct verification |
|---|---|---|---|
| Active OpenSpec contract before implementation | Strict OpenSpec CLI validation | Proposal, design, capability spec, bounded write-set, tasks, and process-level verification plan are valid before production edits | `openspec validate resume-interrupted-workflows --strict` |
| Durable recovery state and correlations | Signed issue POST, process reconstruction on the same SQLite file, then workflow GET | Inbox, run/thread, checkpoint, assignment, worktree, branch, PR, review, repair, and feedback identities survive; recovery exposes bounded operation events | `test_startup_recovery_continues_claimed_run_once_through_http_read_back`; persistence contract suite |
| No duplicate run, worktree, or pull request across claim, implementation, and publication crashes | Real subprocess exit after each durable phase boundary followed by new-process workflow GET and controlled effect counts | Same run/thread completes with exactly one claim, worktree, initial worker, source publication, and draft PR identity | `test_real_process_exit_recovers_completed_effects_without_duplicates[claim|implementation|publication]` |
| Completed transitions are not externally repeated | Persisted operation result plus forced process exit before the next in-memory step | Recovery marks the stable operation `reused`; controlled port count remains one | The same three parameterized subprocess cases plus `test_git_adapter_adopts_the_same_run_owned_worktree_after_restart` |
| Review and repair resume at the missing unit only | Forced exit after one persisted review axis and after one persisted repair invocation | Review retains one result per axis with no repeated requirements review; repair retains one invocation in one round and publishes one new head | `test_real_process_exit_resumes_only_missing_review_axes`; `test_real_process_exit_reuses_persisted_repair_invocation` |
| Feedback continuation preserves batch-local ownership and count | Verified run, signed feedback POST, forced exit after durable attempt completion, new-process GET | Existing feedback batch becomes verified with one attempt; worker/publication/review counts do not increase during recovery | `test_real_process_exit_preserves_completed_feedback_attempt_and_batch_counter` |
| Waiting and completed states do not reactivate | Restart of published waiting run and second restart after authorized human merge | Waiting restart invokes no machine transition; completed run/read model remains identical and effect counts remain unchanged | Startup recovery tests; `test_authorized_human_merge_completes_the_same_run_and_checkpoint_after_restart` |
| Recovery state is data-minimized | Restart after sensitive worker evidence/diagnostics followed by workflow GET | Recovery events expose only ID, phase, stable operation key, outcome, and timestamp; no secret, token, email, webhook body, assignment, or arbitrary exception text appears | `test_sensitive_worker_evidence_and_diagnostics_are_redacted_before_read_back` |
